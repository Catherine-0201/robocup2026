# 总状态机完善记录

## 已修复

1. 新目标下发前先取消旧目标、关闭PID并发布零速度，避免旧路径继续驱动车辆。
2. 新目标发送后等待全局路径更新，再将PID切换到路径跟踪状态。
3. 启动时检查`move_base`和`/pid_planner_status`，缺失时安全退出。
4. 到点信号按“本次目标发送后收到的新事件”判断，可兼容PID节点重启后计数归零。
5. 到点同时核对`/unified_pose`距离，默认禁止仅凭距离判定完成。
6. 记录到点位置误差、航向误差和完成信号来源。
7. 扫码结果默认要求在护士台发出扫码请求后新收到，避免旧任务码污染下一场比赛。
8. 修复`station_done_event.clear()`时机，避免快速动作节点的完成信号丢失。
9. 异常、超时、定位丢失、依赖缺失和程序崩溃时统一执行安全停车。
10. 返航后连续零速保持超过5秒，并区分完整完赛与部分任务返航。
11. 修复总控床位容差小于底层PID停止容差导致的永久等待问题。

## 仍需实车完成

1. 在正式地图重新记录护士台、1床、3床和起点坐标。
2. 接入实体启动按钮和硬件急停。
3. 接入二维码节点，发布`/competition/task_code`。
4. 实现床位精确停靠、条码、药箱、机械臂、语音、音视频与生命体征子状态机。
5. 床位全部动作完成后发布`/competition/station_done=true`。
6. 根据底盘外接圆半径验证完整车体进入半径300 mm圆圈。
7. 台架、空场、障碍物场景依次测试后再进行全流程运行。
